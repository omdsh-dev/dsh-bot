# 长期记忆

在「设置 → 记忆」中管理长期记忆。聊天原文和 DSH Session 仍保留原有职责；长期记忆是单独的结构化记录，不会把所有历史消息重新塞进每次请求。

## 范围与身份

| 范围 | 用途 | 默认读取边界 |
| --- | --- | --- |
| 全局 | 当前部署共同知识、默认约定 | 当前部署全部 Bot、聊天 |
| Bot | 某个 Bot 的工作方法、默认偏好 | 手工录入的记录适用于该 Bot；聊天提取的记录只适用于来源聊天 |
| 群聊 | 群内约定、决定、项目状态 | 该群中的 Bot，其他群不可读取 |
| 用户 | 每位用户自己的偏好、背景 | 默认仅本人私聊；从群聊提取的内容只在来源群中使用 |

Web 当前使用本地配置身份 `local:operator`，并非多租户账号系统。如流和飞书使用平台、接入账号、发送人 ID 的组合，不按昵称合并，也不会自动关联不同平台或不同应用的账号。管理端可以显式关联已核实属于同一人的账号；关联后可在各自私聊召回个人记忆，来源群限制仍然生效。本地用户不能与外部账号合并。解除关联后，共同身份下的记录保留在管理页，但各账号不再自动召回它们。共享群收件记录使用首个认证来源作为稳定用户身份；其他账号身份保持独立。定时任务不继承某个人的用户记忆。

用户记忆可显式设为在所属范围内共享，此后仅在该用户发言时参与其群聊检索。用户的私聊记忆不会因参与群聊而自动变为群记忆。Web 发往外部私聊的本地消息也不加载本地用户的私密记忆，避免污染该外部用户复用的 Session。

管理面板及其 Remote API 属于现有 DSH 原生管理端的权限范围，可以管理所有用户的记忆。它们不是提供给聊天参与者的开放 API。普通状态快照、连接器快照和实时 feed 不包含记忆库。

## 写入与确认

- 管理面板录入后生效。事实必须提供证据或来源说明，可以指定生效时间和到期时间。
- Bot 的 `bot_memory_propose` 工具可以从当前人类消息中提取候选。服务器决定用户身份和来源，工具不能写全局，也不能指定其他用户。必须提供当前消息中真实存在的原文引句。
- 对话结束且聊天空闲后，后台整理会使用回复 Bot 的模型提取候选，不要求 Bot 主动调用工具。队列随状态持久保存，进程重启后恢复；失败按 1/5/15 分钟退避，连续三次失败后等待人工处理，其他条目继续。整理开关、重试、跳过和用量位于记忆面板。关闭整理后不会补扫关闭期间的旧消息。最多保留 200 条待处理/失败任务及最近 100 条已结束任务；队列满时记为跳过，可在保留期间手动重试。
- **候选会持久保存，但全部需要管理端确认后才参与检索。** “记住/以后”可触发 Bot 提出候选，当前版本不自动把模型判断升级为权威事实或群规。工具未开放或 Bot 权限禁止该工具时，仍可在面板手工录入。
- “这次/本次/不要记住”等临时或拒绝记忆的请求不接受工具写入。定时任务和外部聊天中的 Web 本地专用消息也不能生成候选。
- 确认及普通编辑保留原来的私聊/来源聊天限制。提升到其他范围必须勾选共享，并创建副本，保留原记录；不会自动把私聊内容推广到 Bot 或全局。

编辑会生成新版本并替代同一所有者的旧版本；并发修改通过版本号检查，过期编辑会被拒绝。遗忘会清空该条及其被替代版本的内容、主题和证据，并停止后续检索。已明确共享到其他范围的副本独立管理。

## 冲突与检索

先按作用域、身份、来源聊天、状态和有效期过滤，再做中英文词项检索。偏好/约定始终参与候选；事实按问题相关度参与。相同「类型 + 主体/环境 + 主题键」视为同一属性，因此编辑时应复用稳定主题键。例如 `response / language` 或 `project-x/production / release-date`。

偏好按群聊、用户、Bot、全局的顺序覆盖；不冲突的偏好继续生效，底层记录不会被删除。同一优先级的不同表述作为待核实冲突保留。当前明确请求可覆盖已存的个人偏好，群内公开输出仍遵守群约定。记忆内容不能改变工具权限、文件沙箱或其他部署限制。

事实不按范围或记录时间直接覆盖。相同主体和主题的不同内容同时携带证据进入冲突组，要求模型核实；管理员可根据证据编辑替代旧记录。系统不声称能自动验证事实真假或识别所有语义等价主题。

每次最多加载 12 条、8,000 个字符；这是字符预算，不是模型精确 token 预算。冲突组整体进入或整体跳过，避免截掉反面证据。预览显示加载记录、冲突和因预算省略的数量。

## 上下文与存储

记忆记录和候选按每 128 条写入带内容校验的 `bot_memory_*` 原生存储分片，`bot_mode` 保存分片清单，并与所有者、整理队列和身份关联使用相同的串行原子提交。未变化分片不随聊天更新重复写入。旧版内联 `memories` 自动迁移，无需清空聊天。新清单提交后清空失效分片内容，失败清理在后续写入及重启后重试。备份必须同时保留整个 DSH 数据目录中的清单、分片及 Session，不能只复制 `bot_mode` 文件。

检索结果以标明来源的 JSON 数据帧加入当前用户输入，随原生 Session 日志持久保存；系统提示只定义使用规则。最新数据帧包含记录 ID 和版本，便于审计。旧帧可能过期或被遗忘，模型被明确要求仅使用本次帧作为长期记忆来源。

遗忘或变更账号关联会提升部署内的记忆版本，停止当前 Bot 执行、待处理协作和问题续答，并跳过尚未完成的旧记忆整理。各成员下一次请求改用新 Session，不从旧 Session 生成摘要，避免把失效记忆再次带入上下文。这是部署范围的失效操作，会影响其他正在进行的 Bot 任务。过期记忆也不再召回，并在后续请求切换 Session。

遗忘不会重写既有聊天、模型回答、原生执行日志或备份；查询聊天仍可能找到原文。已明确共享的副本独立管理。因此遗忘是撤销长期记忆及旧上下文的继续使用，不是删除所有历史中出现过的文字。

当前没有向量数据库、自动跨平台身份关联或独立多租户 ACL。记忆数量达到 5,000 条有效/候选记录后需先遗忘不用的内容。模型工具每条人类消息最多提取 8 条；同消息、同所有者、同内容的重复提案幂等。


## 主动查询与长对话

Bot 在当前执行中可调用 `search_chat` 搜索当前聊天的旧消息，使用 `read_chat` 读取命中消息及前后文，或通过 `memory_recall` 召回当前身份可见的记忆。工具不能指定其他房间，外部聊天不会返回本地专用消息。权限依旧受 Bot 工具策略约束。聊天索引按需建立中英文倒排表，搜索最多返回 20 条摘要，单条正文最多读取 8,000 字符；超长内容标明截断。索引在内存中，重启后重建，Host 仍加载完整历史，尚未替换为磁盘全文检索。

每次投递前根据模型公开的上下文窗口与原生 token meter 检查压力；meter 不可用时使用保守的字符估计。超过可用窗口的 80% 时，空闲 Session 通过无工具的模型调用生成结构化交接，涵盖目标、限制、进展、决策、事实、未完成任务、下一步和来源。新 Session 与交接摘要一起提交，原执行仍可按消息进入旧 Session 查看。摘要失败且不足 93% 时保留旧 Session，达到硬阈值则携带明确标为局部证据的摘录切换。模型未公开上下文窗口时不做自动压力轮换。正在等待问题回答的会话暂不轮换。

这是请求边界的轮换；单次执行内部仍由 DSH 原生压缩机制管理。记忆整理与交接调用不带工具，最长 60 秒，均计入对应 Bot 和部署预算。辅助用量面板分别展示两种用途。它们使用 Bot 已选择或已解析的模型；无法确定模型时跳过或重试，不会擅自选择其他供应商。

## 协作与超时

人类允许群聊协作时，`delegate_task` 可登记明确子任务，回复完成后原子派发。保留原来的独立 `@Bot 任务` 写法。`task_status` 查询当前人类请求内的状态。所有直接子任务结束后，系统仅回传一次，唤醒派活者处理结果；失败、中断也作为结果回传，嵌套任务先完成自身汇总。回传保留原始人类授权，不能扩展任务范围。重复任务、正在等待下游的 Bot、每个 Bot 超过 3 次分配或全轮超过 12 次派活会被拒绝；自动结果回调不占分配次数。

停止整轮会取消待处理任务及后续汇总。重启不重放不确定的外部动作：未完成执行标为中断，已具备全部结果的汇总可恢复，已预留的回传不会重复生成。默认 10 分钟无进展、60 分钟总执行或 15 分钟未回答审批后停止当前执行；审批过期不会授予权限。可通过 `idleTimeoutMs`、`executionTimeoutMs`、`approvalTimeoutMs` 配置，均至少 1 秒。停止只撤销本插件持有的执行，不能撤回已经发生的外部副作用。
