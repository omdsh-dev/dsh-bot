# 飞书机器人接入

DSH Bot 0.10.0 的「IM 接入 → 飞书」配置面板支持为每个 Bot 单独创建并绑定一个飞书机器人，也可以绑定已有应用。如流入口、凭据和会话继续保留。飞书插件是独立可选包 `@zzzpyyy/dsh-bot-feishu@0.6.0`，搭配 DSH `0.2.0-rc.2` 和 `@zzzpyyy/dsh-bot@0.10.0`。

本说明适用于主包 `0.10.0`、飞书配套包 `0.6.0`。新版本支持图片/文件/音频入站、失败队列恢复、定时通知，以及在 DSH 中显式勾选后同步本条群消息；默认仍不转发 Web 消息。配置方式和运行条件见[功能使用说明](capabilities.md)。以下命令固定本次发布版本，发布与实机验收状态见[完成记录](feature-completion.md)。

同一个 DSH Bot 可以同时启用飞书和如流绑定。在「IM 接入」的两个平台页分别选择同一个 Bot 并完成配置即可，不需要复制 Bot。两边的凭据、准入名单和启停开关独立；停用一个平台不影响另一个平台。消息记录、模型对话上下文和回复目的地按平台及具体聊天隔离，不自动同步或转发；私聊与群聊也分别保存。同名群不会跨平台合并。共用的是 Bot 指令、模型和工具配置；工具可访问的文件、外部服务及主动写入的记忆仍由部署配置决定，不属于会话隔离。

## 一个 Bot，四种调用入口

四个入口使用同一个 DSH Bot 的身份、指令和原生执行预设（模型、工具、技能及审批），回复返回发起请求的聊天。

飞书机器人直接发送回复正文，不额外添加 DSH 内部的 `@botId` 行；发送者名称和头像标明回复身份。模型正文中的正常 @ 文本原样保留。

| 入口 | 触发方式 | 回复位置 |
| --- | --- | --- |
| Web Bot 单聊 | 打开该 Bot，直接发消息 | 当前 Web 单聊 |
| Web 群聊 | 将该 Bot 加入群，发送 `@botId 问题` | 当前 Web 群聊 |
| 飞书 Bot 单聊 | 私聊绑定到该 Bot 的飞书机器人 | 当前飞书单聊 |
| 飞书群聊 | 将机器人加入允许的群，用飞书原生 @ 选择该机器人后发消息 | 当前飞书群聊 |

Bot 的身份和能力共用，聊天上下文按入口和聊天分别保存；Web 私聊内容不会自动带入飞书或群聊。同一飞书群在 DSH 中只显示一个群聊，成员共享公开消息，各 Bot 保留自己的原生 Session；飞书私聊仍按应用隔离。群里存在多个机器人时，只执行被真正 @ 到的机器人；同一条消息 @ 多个 Bot 时，DSH 只记录一条用户消息，并分别展示各 Bot 的回复。文本中手打同名字符串不能替代飞书的原生 @。审批仍在 DSH 完成。

飞书连接已启用仍不代表所有群都开放。进入 **IM 接入 → 飞书 → 选择 Bot**，可以勾选「允许机器人所在的所有群 @ 调用」，或在「允许接入的群 Chat ID」中添加目标群的 `oc_…`，然后保存。所有群开关默认关闭；关闭时空名单不会响应群消息。每个 Bot 独立设置，保存后重启仍生效；关闭开关会恢复原有群白名单。通过一键建群创建的新群会自动配置所选 Bot。私聊用户仍必须在该应用的允许用户名单中。

## 扫码创建并绑定

1. 打开 **DSH Bots → IM 接入 → 飞书**，选择要接入的 Bot。
2. 点击 **扫码创建并绑定**，使用飞书扫描二维码，或打开页面中的官方授权链接。
3. 在飞书确认应用名称、租户和申请权限。此步骤需要你的授权；不是后台静默创建。
4. 返回 DSH。App ID 和 App Secret 会由官方 SDK 返回，凭据直接写入 DSH 凭据库，页面不回显密钥。扫码用户的当前应用 Open ID 会作为默认私聊允许用户和管理员；不同应用的 Open ID 不能互换。
5. 核对绑定结果，点击 **验证机器人**，再点击 **启用连接**。新绑定默认停用，确保先检查配置。

新应用可能仍需发布或租户管理员审批。出现“暂未就绪”时，凭据已保留，去飞书开发者后台完成发布，然后再次验证即可，不要重复创建。

## 绑定已有机器人

选择对应 Bot，点击 **绑定已有机器人**，填写 App ID（`cli_` 开头）、App Secret、允许私聊用户（该应用的 `ou_` Open ID）和管理员。平台可选飞书或 Lark。点击 **验证并保存**，通过后启用连接。

已保存密钥留空表示保留原值。一个 App ID 只能绑定一个 DSH Bot，防止两个 Bot 争抢同一应用事件。已有绑定不能直接换应用；为新应用创建一个新的 DSH Bot。

## 消息、权限和群聊

连接使用飞书官方长连接，不需要公网回调地址。应用需启用机器人能力，在「事件与回调」使用长连接，并订阅 `im.message.receive_v1`。接入申请以下应用权限：

- `im:message.p2p_msg:readonly`：接收用户私聊。
- `im:message.group_at_msg:readonly`：接收群中 @机器人的消息。
- `im:message:send_as_bot`：以机器人身份发送回复。
- `im:resource`：上传图片／文件并读取接收到的消息资源；已有应用需补齐权限后发布。
- `im:chat:read`：读取群名；已有应用需在开放平台开通、发布并完成组织审批。
- `im:chat:create`：创建飞书群；已有应用可点击页面中的「开通建群权限」补齐。

官方创建页的 `addons` 能力仍有灰度限制；若没有采用请求的配置，可能展示默认模板。以实际授权页为准，核对权限，并在开发者后台补齐消息事件、长连接和发布状态。不要同时在其他程序运行同一应用的接收连接。

私聊只接受允许用户；群聊必须明确 @当前机器人，并符合该 Bot 的群白名单或已开启的「所有群」设置。开启所有群后，机器人所在且平台允许接收消息的群中，任何成员都可以 @它执行任务；不会自动将机器人加入其他群，也不会开放私聊。支持文字回复及 `/help`、`/status`、`/stop`；审批仍在 DSH 中处理。

## 一键创建飞书群聊

在 **IM 接入 → 飞书 → 选择已启用的 Bot → 新建飞书群聊** 填写群名，勾选 1–6 个同企业、同平台且已启用的机器人，然后点击「创建」。普通「新建群聊」窗口也可以勾选「同时创建飞书群聊」。DSH 使用指定的建群机器人创建私有群，自动加入群主及所选机器人、补充各 Bot 的允许群列表，并创建对话记录。建群机器人需要 `im:chat:create`；其他被邀请的机器人只需原有消息权限。

群主默认是建群机器人配置的第一位管理员，没有管理员时使用第一位允许私聊用户。高级设置可以填写该应用对应的群主 Open ID；不同应用的用户 Open ID 不能互换。群里用飞书原生 @ 选择机器人即可调用它。DSH 中以群名显示一个共享群聊，包含所有接入成员及其回复。此入口创建飞书群及其记录，不额外创建独立 Web 群。

升级后会自动合并旧版按 Bot 拆开的同群记录，保留原生 Session、回复和待发队列；重复的同一条群消息合并为一条。首次继续执行时，各 Bot 会获得有上限的共享公开历史。原来保存的群聊入口仍可跳转到合并后的群。DSH 内可查看记录、停止响应、打开执行会话，也可显式勾选同步后向群发送文字和附件；飞书内调用机器人仍需原生 @。

如果建群被明确拒绝（例如缺少 `im:chat:create`），弹窗会保留群名和成员并恢复编辑；可以从弹窗打开当前应用的权限页，或改用曾成功建群的机器人。已关闭的失败请求可在「IM 接入 → 飞书」群聊列表点击「修改后重试」恢复草稿。切换建群机器人会清空原应用的群主 Open ID，改用新机器人的默认群主。结果尚未确认或群已创建但接入未完成时，配置继续锁定，点击「继续完成」恢复同一次请求。

建群记录先持久化请求 ID，再调用[飞书创建群 API](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/chat/create.md)。失败时从飞书页面的群列表点击「继续完成」：已保存群 ID 的请求只补齐本地接入，未知结果在原请求的 9 小时内使用相同 UUID 和群主重试（飞书去重期限为 10 小时）；到期后须先确认远端结果，已有群可手动接入。服务重启不会自动重发建群。原有如流建群功能继续可用。

## 取消、重启和重试

取消只停止等待授权，不能撤销已经在飞书确认创建的应用。授权中服务重启后，不会自动重试创建；先检查飞书后台，若已存在应用，使用「绑定已有机器人」。二维码过期后可重新发起扫码。创建结果或本地保存失败也不会自动创建第二个应用。

聊天接收、回复队列和去重记录保存在 DSH 原生存储。连接恢复可继续已接收任务。发送使用稳定的 UUID；飞书服务的去重有效期有限，长时间不确定的网络故障无法保证远端永不重复。

## 安装与开发

DSH 0.2.0 的新 profile 使用 pnpm 11，可能因飞书 SDK 的间接依赖报 `ERR_PNPM_IGNORED_BUILDS: protobufjs`。该依赖的安装脚本只打印版本声明提示，不生成运行所需文件。可在目标 profile 的 `pnpm-workspace.yaml` 中合并以下设置，明确跳过它，再重新安装：

```yaml
allowBuilds:
  protobufjs: false
```

Web 对应 `$DSH_HOME/profiles/web/pnpm-workspace.yaml`，Desktop 对应 `$DSH_HOME/profiles/desktop/pnpm-workspace.yaml`；未设置 `DSH_HOME` 时使用 `~/.dsh`。如已有 `allowBuilds`，只添加这一项，保留其他配置。本项目的真实安装测试使用相同设置。

在兼容的 DSH `0.2.0-rc.2` Web profile 中，先安装主包，再安装飞书插件：

```sh
dsh plugin --profile web add @zzzpyyy/dsh-bot@0.10.0
dsh plugin --profile web add @zzzpyyy/dsh-bot-feishu@0.6.0
```

Desktop 可在插件管理器中按相同顺序安装这两个精确版本。包使用 `next` 标签；使用与现有服务相同的 profile 和数据目录。升级前备份数据并停止 Host，升级后重启，再从「IM 接入 → 飞书」检查连接状态。

构建后运行 `npm run pack:feishu`，得到独立伴随包。该包固定依赖公开的 `@larksuiteoapi/node-sdk@1.75.0` 和 `qrcode@1.5.4`。通过 DSH 原生插件包安装机制加载；Web 使用包内 `cordis.patch.yml`，与基础插件的 patch 一起放在命令行子命令之前。默认只启用管理页，不创建应用、不连接未启用的绑定。可调队列、重试与 HTTP 超时见 [示例配置](../feishu/cordis.patch.example.yml)。

官方依据：[SDK 应用注册](https://github.com/larksuite/node-sdk#app-registration)、[飞书官方扫码创建指南](https://www.feishu.cn/content/article/7613711414611463386)、[实现调研](feishu-provisioning-research.zh.md)。

## 群内 Bot 派活

飞书群中，可以先用平台的 @ 功能对 DSH Bot 说：“请把实现任务交给工程 Bot，再让审阅 Bot 检查。”Bot 会使用单独的 `@engineer 具体任务` 行派活；目标须已在同一个 DSH 群里，且对应平台绑定已启用、连接正常。支持 Bot handle 或唯一的显示名，推荐使用 handle。目标 Bot 在自己的 Session 中执行，并由自己的机器人回到原群，双方共享当前群的公开上下文。

成功创建子任务后，派活消息会附带目标机器人 Open ID 对应的原生 @。任务执行期间，目标机器人会立即回复“已接单”；很快完成的任务直接返回结果。派活由 DSH 内部调度，不依赖飞书转发机器人之间的消息；网络重试或重启不会重新派活或重复创建接单提示。

支持加粗、列表、表格及同一行分号分隔的派活，也支持审阅后回派修复和汇总。同一条用户请求中，每个 Bot 最多执行三次、最多派发十二个子任务；同一任务不重复派发，不能跨群或跨平台派活。目标未接入、正在执行或达到上限时，回复会显示未派发原因。引用、代码、普通提及和 `@all` 不触发 Bot 派活。停止与审批仍归属于原始用户请求；需要停止整条派活链时，请 @ 最初接收任务的机器人发送 `/stop`。

这项能力由 DSH 调度，不依赖平台把机器人消息作为新的用户消息推送。需要同时升级主包至 `0.8.0`，以及飞书配套包至 `0.4.0`／如流配套包至 `0.5.1`。已有如流群同样支持派活：将同一个群号加入各 Bot 的允许群列表即可共享群历史，无需重新建群。开启「所有群」后，首次收到群消息时会加载同平台中已启用、允许该群的 Bot，无需先逐个 @ 一遍。参与派活的机器人仍须实际加入该平台群；该设置不会自动邀请机器人入群。

## 图片、文件与音频权限

应用须启用机器人能力，订阅 `im.message.receive_v1`，保留私聊读取、群内 @ 消息读取、机器人发送消息权限，并申请 `im:resource`（获取与上传图片或文件资源）。自动注册流程会申请这项权限；已有应用需在开放平台补齐、发布新版本并完成组织审批后再测试。机器人必须在目标群中；「所有群」只放开 DSH 的准入列表，不会让机器人自动入群。

入站用消息 ID 和资源 key 调用 SDK `im.messageResource.get`，出站先上传得到 image_key/file_key，再发送图片／文件消息。音频识别另需 DSH speech-to-text；压缩音频需主机 ffmpeg。权限失败和下载／转写失败均保留在失败队列，修正配置后可单项重试。

依据：[消息能力与权限总览](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1)、[上传图片](https://open.feishu.cn/document/server-docs/im-v1/image/create)、[上传文件](https://open.feishu.cn/document/server-docs/im-v1/file/create)。

### 群名同步

Bot 0.12.3 与飞书连接器 0.6.2 支持以下自动来源，Bot 0.12.4 另外支持对话补齐：

- **事件推送**：订阅 `im.chat.member.bot.added_v1`（机器人进群）后，从事件 `name` 保存入群时的名称。符合当前绑定允许群列表（或已启用“所有群”）的新群会出现在 Web 中，无需先发消息。订阅 `im.chat.updated_v1`（群配置修改）后，从 `after_change.name` 同步改名；仅修改头像等其他字段的事件不会清空群名。
- **群信息查询**：首次群消息、服务启动及后台定期刷新会查询群名，为已有群补齐名称。查询失败或返回空名称时保留已知名称；先前查询和排队消息不会覆盖刚收到的事件名称。

进群事件需要 `im:chat.members:bot_access`，或接口认可的等效权限。只开通这项权限也能记录入群时的群名，但无法补查未收到事件的历史群，或持续追踪后续改名。群信息查询与改名事件需要 `im:chat:read`、`im:chat:readonly`、`im:chat` 中适用的群信息权限；通常申请较窄的 `im:chat:read` 即可。普通消息事件只有群 ID，不提供群名称。

新应用扫码创建会一并申请进群权限并订阅上述事件。**已有应用**需在飞书开放平台开启权限，在长连接事件列表中添加“机器人进群”“群配置修改”，发布应用并完成组织审批。Web 的 **IM 接入 → 飞书 → 对应 Bot → 群名同步设置** 提供说明和权限链接。更新本地连接器不会自动修改已发布应用的权限和事件列表。

自动更新保留群 ID、聊天记录和默认 Bot；进群事件仅加入当前已授权绑定的 Bot，不扫描或接入未允许的群。不调用模型、不发送 IM 消息。连接期间按事件时间忽略旧事件；收到重投时可重试失败的持久化。重启保留已保存群名；历史事件时间只在当前连接内去重，跨重启的完整校正仍依赖群信息查询。

依据：[机器人进群](https://open.feishu.cn/document/server-docs/group/chat-member/event/added-2)、[群配置修改](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/chat/events/updated)、[获取群信息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/chat/get)。

#### 在群聊中补齐名称

当前机器人在 **IM 接入 → 飞书 → 对应 Bot → 管理员** 中配置的用户，可以在群内原生 @ 机器人说：

> 这个群叫「产品讨论群」，帮我补齐到 Web。

Bot 通过 `set_group_name` 保存当前群在 Web 中的显示名，聊天列表会随状态更新。这个操作不需要 `im:chat:read`，但仍需正常接收管理员消息；不会修改飞书里的实际群名。后续授权查询或收到群名事件时，以 IM 的实际名称继续同步。

只支持当前群内管理员的直接请求，私聊、Web 本地消息、普通成员、定时任务和 Bot 委派不能执行。名称必须在当前请求中明确给出；只说“同步群名”但拿不到名称时，Bot 会询问名称，不会根据聊天内容猜测。一次回复最多保存一个名称；重复工具调用不会把后续更新回滚。名称和操作记录随聊天持久化，重启后保留。

#### 群名权限提示与默认申请

Bot 0.12.6 与飞书连接器 0.6.4 将群信息查询结果显示在 **IM 接入 → 飞书** 的机器人列表和连接详情中。只有接口明确返回缺权限错误 `99991672` 才显示“群名读取权限未生效”，并给出当前应用的 `im:chat:read` 开通入口、发布与组织审批步骤。群名查询失败不影响消息连接状态。网络错误、其他群访问错误和空响应显示“群名暂未读取成功”，不会被当成缺权限；未查询过的应用显示“群名读取尚未验证”。后续查询成功后自动清除提示并同步群名。

当群里询问群名或同步问题时，Bot 的当前上下文会带上自身应用的缺权限状态与开通链接；对话补名工具成功后也可返回同一指引。普通聊天不要求重复提醒，不会额外向群里发送后台通知。

扫码创建应用已经默认请求 `im:chat:read`，现在创建入口也明确说明。默认申请不等于跳过飞书确认：已有应用仍需应用管理员开通权限，按平台要求发布并完成组织审批。DSH 不自动修改已发布应用的授权范围。

飞书存在免审权限场景，应以当前应用授权页面的要求为准，不将发布或组织审批视为所有应用都必须重复执行的步骤。参考：[官方权限开通教程](https://open.feishu.cn/document/introduction-2?lang=zh-CN)。
