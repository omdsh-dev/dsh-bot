# One DSH Room per Feishu group

Feishu group identity belongs to BotMode and uses the platform chat ID, with `group:<chatId>` as its canonical external account key. Group provisioning and manually allowed groups add their Bots to that Room. Private chats retain app-specific identities. Every membership retains its own native Session and execution identity; members receive the bounded public history through the normal context cursor.

The authenticated transport accepts a group event only when it mentions that receiving robot. Each app submits only its own Bot target and retains its existing durable queue. BotMode commits one human message per platform message ID and one response per target in the same transaction. A later callback for a second mentioned Bot adds that missing response without repeating the human row or the first Bot's execution. Each caller receives only its target's attempt IDs, so replies are sent by their owning app. Platform mention placeholders are stripped consistently; the first authenticated text copy is retained. Human sender aliases record the original app and Open ID, rather than treating Open IDs from different apps as interchangeable.

Startup merges legacy group Rooms in one BotMode write, preserving native Session IDs, response IDs and histories, deduplicating repeated human receipts and remapping their reply parents. Retired Room IDs remain aliases for persisted pending replies and saved selections. Cursors reset once to make the merged bounded history available on continuation. A conflicting Session for the same Bot is rejected rather than discarded. Group manager records are relinked before receivers activate. No external message or model call is issued by migration. Queues, credentials, private chats and InfoFlow identities retain their ownership.

Attention notices and group `/stop` resolve the shared Room but act through the receiving Bot only. Stop authorization uses the sender's Open ID for that app, or that app's administrator list. DSH continues to expose external history, execution details and stop controls; users send text and native mentions in Feishu.

Validation covers source-level migration, duplicate receipts, app-scoped stop and attention, plus a native packaged Host with the official SDK dispatcher. The native test exercises separate and multiple mentions, late callbacks, duplicate delivery, private-chat isolation, shared public context, clean restart, legacy migration and a retained pending reply pointing to a retired Room ID without a new model execution.
