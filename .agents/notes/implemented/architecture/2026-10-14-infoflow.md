# Optional InfoFlow ingress and durable delivery

The connector runs inside the DSH Host and depends on BotMode. A separate companion archive owns the private SDK dependency and inserts a disabled plugin row. No Multica service, account profile, issue board, login flow, or Agent loop modification is introduced.

External Room identity is the tuple of provider, application account, conversation kind, and conversation ID. External DMs never reuse a Bot's canonical local DM. Groups share an admitted public history with named human senders. Human display names are logged as user data and excluded from system identity instructions. Platform IDs remain strings.

The Bot owner atomically records each external message receipt together with its human message and response attempts. Its Host-only submission method returns the original IDs on redelivery. The connector atomically stores its own receipt and pending input before acknowledging acceptance. A single admission/dispatch mutex prevents stop from canceling a pending record while the same record is being committed to BotMode. Network delivery does not hold that mutex.

Final responses enter a separate durable outbox before the pending input is removed. Individual chunks are removed only after a send resolves. Platform acknowledgement loss can duplicate external text; it never retries model or tool execution. A process crash keeps uncertain Bot work interrupted. Changing account configuration cannot redirect previously captured recipients. Queue and dedup capacity limits fail admission before claiming a receipt.

The pinned single-document storage backend rejects a domain version change and exposes no migration API. BotMode therefore retains envelope version 1 with additive optional external fields. Legacy Bot, Room and Session IDs remain unchanged. Downgrading to older code that strips unknown fields is unsupported. Native Session storage is untouched.

Native approval audit events and user-question requests produce notices without supplying answers or changing permission policy. DSH owns the answerers. Tests exercise fault paths through the bridge interfaces, SDK calls with fixtures, and native profile crash/restart. A separate archive test boots the companion with a fixture SDK in the production Desktop dependency closure. Real enterprise registry, gateway and permission validation is outside these keyless tests.
