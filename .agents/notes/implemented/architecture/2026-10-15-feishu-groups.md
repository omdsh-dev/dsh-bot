# Durable Feishu group creation

The Feishu manager owns explicit private-group creation and retains requests in the additive `groups` field of `bot_feishu_settings`. Existing v1 stores load with an empty group list. The public Remote interface exposes create/resume; the configuration page and new-chat dialog use the same operation. Existing InfoFlow creation remains independently owned.

A request records the normalized roster, creating Bot, resolved app-scoped human owner and original timestamp before an external call. The official API receives a stable request UUID, owner, and other robots’ App IDs. A returned chat ID is committed before allowlists, native rooms or receivers change. Local partial failure resumes against that ID. Unknown remote outcomes can retry the same UUID and owner for nine hours, within Feishu’s ten-hour deduplication guarantee; they never retry automatically at startup or after that window. Permission errors are sanitized and distinguishable from uncertain network outcomes. Registration requests the additional minimal `im:chat:create` scope; existing apps use the visible permission link.

All selected Bots must exist, be enabled and use the same Feishu/Lark platform. One API call can invite at most five other apps. The manager adds only the created group to selected bindings, retains all other settings, and restarts their receivers after persistence. Each app keeps its independent bridge queue and native Session. The group now resolves to one shared Room under the [shared group decision](2026-10-15-feishu-shared-groups.md), returned for navigation. User Open IDs remain app-scoped even when the human message receipt is shared.

Validation covers source manager failure/retry/restart and expired deduplication, SDK response classification and wire parameters, the selected-Bot UI workflow, and the packed native Host with two robots automatically allowed into the created group. The native fixture exercises actual routing, replies, isolation and restart without manual allowlist edits. Browser acceptance creates a real group from the installed page and verifies platform @ replies.
